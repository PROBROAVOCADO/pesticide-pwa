# 田間用藥 PWA

查詢農業部公開的殺菌劑、殺蟲劑登記資料，並依作物、施用面積與實際用水量逐項試算藥量。

線上版：https://pesticide.probroavocado.com

## 這是純靜態網站，沒有建置步驟

所有檔案都是瀏覽器直接讀得懂的原生格式。把整個資料夾的檔案丟到 GitHub，
Pages 設定成 **Deploy from a branch → main → / (root)** 就會直接生效，
不需要 npm、不需要 GitHub Actions。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `index.html` | 頁面骨架、PWA meta、字型與樣式連結 |
| `styles.css` | 全站樣式（含 900px 以上改側邊欄的斷點） |
| `app.js` | 主程式：狀態、動作、事件處理 |
| `views.js` | 畫面組裝（純函式：吃資料、吐 HTML） |
| `calc.js` | 單位換算與用量試算（面積用藥量與稀釋倍數的交叉檢核） |
| `records.js` | 施作紀錄邏輯：安全採收期推算、剪貼簿文字、行事曆匯出 |
| `db.js` | 本機資料庫（IndexedDB）：土地、施作紀錄、藥劑快取、備份 |
| `moa.js` | 農業部 API 存取與欄位處理 |
| `sw.js` | Service Worker，離線外殼 |
| `manifest.json` | PWA 安裝資訊 |
| `CNAME` | 自訂網域，GitHub Pages 逐字比對，不要改動格式 |
| `favicon.svg` | 分頁圖示（藍色格狀），也是主畫面圖示的來源 |
| `icon-192.png` `icon-512.png` | 主畫面圖示（purpose `any`），內容佔 76% |
| `icon-maskable-512.png` | Android 自適應圖示（purpose `maskable`），內容只佔 56% |
| `package.json` `calc.test.js` `records.test.js` `moa.test.js` | 只用來跑測試，跟網站運作完全無關 |

`app.js` 用 `<script type="module">` 載入，瀏覽器會自己處理 `import`。

## 在電腦預覽

不能直接用檔案總管點開 `index.html` —— ES modules 需要透過 HTTP 才能載入。
裝了 Node.js 的話，在這個資料夾執行：

```
npx serve
```

然後開它顯示的網址。VS Code 的 Live Server 擴充套件也可以。

## 跑測試

計算、紀錄與資料比對的部分有 103 個單元測試，涵蓋官方資料的各種雜格式、
日期推算、行事曆檔案格式與作物名稱的異體字比對。不需要安裝任何套件：

```
node --test
```

### 圖示為什麼要三個檔案

Android 的自適應圖示會把 `maskable` 的圖裁成圓形或圓角方形，
安全區只有中心直徑 80% 的圓，內接正方形約邊長 56%。
同一張圖同時宣告 `any` 與 `maskable` 是常見錯誤 —— 留白不夠時，四個角的方塊會被切掉。
所以 `any` 用的兩張留白較少（看起來大），`maskable` 那張留白較多（不會被裁到）。

要重做圖示時，改 `favicon.svg` 之後用 cairosvg 重新輸出，
把 SVG 依比例縮放後貼在白底畫布中央即可。

## 發版流程

1. 改 `app.js` 裡的 `VERSION`。
2. 改 `sw.js` 裡的 `CACHE` 版本號（**一定要改**，否則使用者拿到的還是舊檔案）。
3. 更新 `app.js` 裡 `modalHtml()` 的 release 說明文字。
4. 把改過的檔案上傳到 GitHub。

## 資料來源與限制

- 農業部「農藥資料查詢」公開資料，每週更新。
- 動植物防疫檢疫署「農藥資訊服務網」核准使用範圍。
- 試算是單位換算工具，不判斷混配相容性、藥害或現場施藥條件；實際施用以產品中文標示與最新公告為準。

### 為什麼不再依分類過濾

以前只收「殺菌劑」與「殺蟲劑」，而且是**完全相等**比對，所以「殺菌殺蟎劑」這種
複合寫法會被整筆丟掉，畫面上完全沒有痕跡。更根本的問題是：
**把農友手上可能有的藥藏起來，比列出來讓他自己判斷危險得多** ——
他只會以為那支藥沒登記。

現在改成標示：除草劑、殺蟎劑照樣列出，卡片上標清楚分類。

### 許可證狀態：撤銷之外還要看有效期限

`撤銷類別` 是空的**不代表還有效**。例如農藥進02068（銅右滅達樂）的有效期限是
`106/12/13`，也就是 2017 年，但撤銷類別是空白 —— 只看撤銷類別會把它當成有效藥劑列出來。

`licenseStatus()` 兩個欄位都看，回傳 `valid` / `expired` / `revoked`。
過期與撤銷的照樣列出（農友手上可能還有庫存），但卡片會變色並標示狀態，
排序時也會沉到有效藥劑後面。

### 為什麼卡片要同時顯示商品名與普通名

- 廠牌名稱（商品名）—— 農友去農藥行報的是這個
- 中文名稱（普通名）—— 農友是用這個在搜尋

只顯示其中一個都會出事。廠牌名稱空白時全部退回普通名，一整排都叫「賽洛寧」分不出來；
只顯示廠牌時，打「滅達」想找「銅右滅達樂」，畫面上出現的卻是「金手指」「立達樂」，
東西明明在清單裡卻認不出來。

所以兩個並列，再用 `highlight()` 把搜尋字串標成黃底。
`highlight()` 是逐段 escape 之後才拼接的，只有 `<mark>` 是我們自己插進去的字面標籤 ——
官方資料裡的任何角括號都不會變成 HTML。

### 「已核准優先」涵蓋到哪裡

每一支藥都要單獨發一次請求才知道有沒有核准用於某作物（作物不在主資料裡），
所以只掃前 `APPROVAL_SCAN_LIMIT`（40 支）。畫面一定要寫清楚掃到第幾支 ——
一個只保證前面幾支準確的「已核准優先」，比不排序更會誤導人。

排序依序看：核准狀態 → 許可證狀態 → 原本的相關度。第二層是必要的，
否則一張 2017 年就到期的許可證會被推到第一名。

### 查詢結果為什麼可能不完整

官方單次查詢有筆數上限（`MOA_TOP`，目前 200，在 `moa.js`）。像「亞托敏」這種
普通名稱，登記產品可以上百支，排在後面的廠牌會被截掉。三個做法一起解決：

1. `MOA_TOP` 拉高到 200。
2. 只要任一欄位回傳筆數達到上限，就判定為被截斷，畫面明講「可能還有沒列出來的產品」。
3. 結果區上方有「在這 N 筆結果裡再找」的篩選欄，可就地用廠牌、廠商、許可證號縮小範圍。

**被截斷時一定要講出來。** 使用者看到清單裡沒有某個廠牌，會直接認定它沒登記 ——
那比查不到還危險。

### 作物查詢為什麼有範圍限制

官方的 `PesticideData` 只能用**藥劑名稱、廠牌、代號**篩選，作物不在裡面 ——
作物藏在每一支藥各自的「農藥使用範圍」子資料，要一支一支去抓才看得到。所以：

| 你填了什麼 | App 怎麼查 |
| --- | --- |
| 只填藥劑名稱 | 直接查官方，最完整 |
| 藥劑名稱＋作物 | 先用藥名查，再逐一拓展使用範圍比對作物。每一支都是一次請求，所以上限 `CROP_SCAN_LIMIT`（24 筆），被截掉時畫面會明講 |
| 只填作物 | 官方端做不到，改翻這台裝置查過的藥，畫面會說明範圍限制 |

要放寬只填作物的查詢，得另外找一份「使用範圍」的完整資料集，或自己先把資料整理成一份靜態檔隨 App 發布。

## 資料保存在哪裡

使用者的資料只存在自己的手機瀏覽器裡，不上傳任何後台。

| 存在哪 | 放什麼 |
| --- | --- |
| IndexedDB `field-meds-pwa` | 土地、施作紀錄、查過的藥劑快取 |
| `localStorage` `field-meds:` 前綴 | 只有「看過哪個版本說明」這種輕量偏好 |

`applications` 存的是**當下的快照** —— 土地名稱、面積、官方標示的安全採收期與施藥間隔
全都複製一份進去，而不是參照 `fields` 或即時抓官方資料。
農藥登記會被撤銷、標示會改、土地可能重新丈量，
但「那天實際做了什麼」是不變的事實，不能被日後的異動改寫。

儲存空間綁在**網域加路徑**上，所以 `pesticide.probroavocado.com` 一旦上線就不要再改，
改網址等於把所有使用者的紀錄清空。同理，`DB_NAME` 也不要動。

### 常用藥劑的數量上限

| 分組 | 上限 | 在哪改 |
| --- | --- | --- |
| 我釘選的 | 沒有上限 | — |
| 最近用過 | `RECENT_DRUG_LIMIT`（10 支） | `app.js` |

「最近用過」是從施作紀錄自動推出來的：同一支藥只會出現一次，依最近一次施作日排序，
已經釘選的不會重複列在下面。

### 匯出檔名的取捨

備份檔用中文檔名（`田間用藥2026-08-28.json`），因為使用者要在手機的檔案 App 裡找得到。
行事曆檔用英數字（`spray-2026-08-28.ics`），因為部分 Chromium 版本遇到含中文的
`download` 屬性會整個放棄，存成沒有副檔名的 `download` —— 備份檔還能手動改名，
`.ics` 掉了副檔名就完全打不開。

## 這個工具不做什麼

- 不判斷兩種藥劑能不能安全混用。數學上用量與稀釋條件都成立，不代表相容。
- 不阻止使用者保存「不合理」的紀錄。紀錄必須忠實反映實際發生的事，
  App 只能警示，不能把紀錄功能當成審核功能。
- 推算的採收日只根據**這台裝置上的紀錄**。漏記的施藥不會被算進去。
- 「其他添加物」只是忠實記下你加了什麼，不做任何相容性或安全性判斷，
  也因為沒有官方安全採收期而不列入採收日推算。
- 自訂配方／資材只會依實際用量與用水反推當次稀釋倍數，不會產生農業部建議稀釋或安全採收期。
